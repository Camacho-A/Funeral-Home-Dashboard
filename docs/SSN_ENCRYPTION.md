# Case SSN encryption key (`SSN_ENCRYPTION_KEY`)

Case SSN (2026-10, `domain/cases/caseSsn.ts`, `services/caseSsnService.ts`)
stores a decedent's Social Security number on the case, captured from the
Arrangement Form (else Vital Statistics form), encrypted with AES-256-GCM
(`lib/identity/ssnEncryption.ts`). The key is `SSN_ENCRYPTION_KEY`.

## Current state (2026-10-28)

- Code deployed (`70bae4d`); **the key is not set**, so the feature is inactive.
- Without the key in production nothing is stored or captured
  (`isSsnEncryptionConfigured()` is false), the case shows "Not on file",
  an administrator's Correct/Enter is refused with "not set up yet", and the
  Manatee County application reads the SSN from the intake form as before.
- Verified read-only against live data: 0 of 12 Manors cases carry the
  `ssnProtected` field; 0 `case.ssn_*` activity events.

## Generating the key

- 32 random bytes from a cryptographically secure generator, generated by an
  administrator on their own machine — for example `openssl rand -base64 32`.
- Never generated by, pasted into, or shown to an AI assistant, chat, ticket,
  email, document, screenshot, commit, or log.
- Its own key: never reuse `CALENDAR_TOKEN_ENCRYPTION_KEY`, `MFA_ENCRYPTION_KEY`,
  `SESSION_JWT_SECRET` or any other secret.

## Storing it

- Vercel project `manors-cremation-dashboard` → Environment Variables →
  `SSN_ENCRYPTION_KEY`, **Production only**, marked **Sensitive** (write-only
  in the dashboard). Redeploy for it to take effect.
- **Not in Preview.** Preview deployments read the live Wix data; with no key
  there, Preview simply stores nothing (fails safe). A different Preview key
  would write SSNs Production could never read.
- **Not in `.env.local`** pointing at live data. Local development uses the
  built-in development key with fictional data only.
- An **offline backup copy** in the organization's password manager / secure
  vault, readable by the owner and one named backup administrator — separate
  from Vercel. Record who holds access and when the key was created.
- Restrict who can view or edit the Vercel project's environment variables.

## Recovery

- **If the key is lost, every stored SSN is unreadable.** Nothing else
  breaks: decryption failures are treated as "not on file" (logged without
  detail), and the Manatee County application falls back to the intake form.
- A stored-but-unreadable SSN is still "on file", so a new form will not
  replace it (captures never overwrite). Restore the key from the backup copy;
  if that is impossible, an administrator re-enters each affected case's SSN
  with Correct… (recorded with a reason). A bulk re-capture tool does not
  exist yet and would need to be built and approved.

## Rotation

- The code reads **one key**. Changing `SSN_ENCRYPTION_KEY` without
  re-encrypting makes every stored SSN unreadable.
- Before the first rotation, a re-encryption step must be built and approved:
  decrypt each case's `ssnProtected` with the old key and re-encrypt with the
  new (old and new keys present together only for that run), verify every
  record, then remove the old key.
- Rotate when the key may have been exposed, when someone with access to it
  leaves, or on the organization's scheduled rotation (e.g. yearly). Keep the
  retired key in the vault until rotation is verified, then destroy it.

## Activating (requires approval)

1. Administrator generates the key locally and saves the backup copy.
2. Adds it to Vercel Production as `SSN_ENCRYPTION_KEY` (Sensitive), then redeploys.
3. Opens the Manatee County application on one test case: the SSN should then
   show as locked (•••-••-1234) in Case Information and the case activity
   should record "Social Security number saved and locked".
